# 강화 성장 축과 전설검 등급 — 설계

2026-07-29

## 왜 하는가

무한 구간의 강화가 **맨몸으로는 극악**이다. +45 기준 성공률이 0.5% 바닥이고 실패는
반드시 파괴다. 담금질을 넣어 한 단계 중앙값이 138번에서 23번으로 줄었지만, 그것뿐이다.
**플레이어가 오래 해서 얻은 것이 강화 확률로 이어지는 길이 없다.**

동시에 계열 14종이 여전히 외형뿐이다. 계열을 모아도 강화가 나아지지 않는다.

두 문제를 한 구조로 푼다. **오래 한 것이 강화 확률로 쌓이게** 하고, 그 끝에
**전설검**이라는 도달점을 둔다.

## 축이 둘이다

```
축 1 — 강화 확률 성장          축 2 — 전설검 등급
  ForgeBonus (합산 한 곳)        계열은 +20 상한
    ← 도감 수집                  +21 은 조합으로만
    ← 대장간 스킬                허검 완화
    ← 고유검 보유                전설 해금
    ← 계열 특성
    ← 전설검 착용  ←──────────────────┘
```

**축 2가 축 1에 꽂힌다.** 「전설검이 되면 뭔가 오른다」가 결국 축 1의 보너스이므로
축 1의 뼈대가 먼저 서야 한다.

## 하지 않는 것

- 전설검으로 **사냥이 쉬워지지 않는다.** 전투 배수는 건드리지 않는다 —
  [BossTempoTest] 가 잡아 둔 「권장 +2에서 보스가 잡힌다」 곡선을 지킨다.
  어렵게 얻은 검의 값어치는 **강화 쪽**으로 돌려준다.
- 유한 구간(+20 이하) 확률표를 바꾸지 않는다.
- 아이템 가격·사냥 수입을 다시 만지지 않는다. 방금 정렬한 곳이다.

# 축 1 — 강화 확률 성장

## 1-1. 합산은 한 곳에서만

`core/.../ForgeBonus.kt` 를 새로 만든다.

```kotlin
/** 강화에 얹히는 보너스의 합. 출처가 몇이든 여기 한 곳에서만 더한다. */
data class ForgeBonus(
    /** 성공률에 더하는 몫(%p 아님, 0.012 = 1.2%p). */
    val successRate: Double,
    /** 파괴 판정을 무효로 돌릴 확률. */
    val destroyGuard: Double,
) {
    companion object {
        val NONE = ForgeBonus(0.0, 0.0)
        fun of(state: GameState, progress: ProgressState): ForgeBonus
        /** 화면이 출처별로 쪼개 보여 줄 수 있게 낱개로도 낸다. */
        fun breakdown(state: GameState, progress: ProgressState): List<BonusSource>
    }
}

/** 보너스 한 줄. 화면이 "왜 이 확률인지" 말해 주기 위한 것이다. */
data class BonusSource(val label: String, val detail: String, val bonus: ForgeBonus)
```

여러 곳에서 더하면 **왜 이 확률이 나왔는지 아무도 설명 못 하게 된다.** 그래서 화면도
합계만 보여 주지 않고 출처별로 쪼갠다.

```
성공률 12.4%
  기본        0.5%
  도감        +2.1%   (214/324)
  대장간      +1.8%   (Lv 9)
  고유검      +0.9%   (3/10)
  담금질      +7.1%   (28회)
```

## 1-2. 출처와 상한

| 출처 | 단위 | 최대 성공률 | 최대 파괴방지 |
|---|---|---|---|
| 도감 | 10칸마다 +0.1%p | +3.2%p | +3.2% |
| 대장간 스킬 | 레벨당 +0.2%p | +3.0%p (Lv15) | +3.0% |
| 고유검 보유 | 1종당 +0.3%p | +3.0%p (10종) | +3.0% |
| 전설검 착용 | — | +3.0%p | +3.0% |
| **합계** | | **+12.2%p** | **+12.2%** |

**왜 이 크기인가.** +45 기준 0.5% → 12.7%. 한 단계 중앙값이 **23번에서 6번**이 된다.
담금질이 그 위에 또 얹힌다. 「극악」이 「해볼 만함」이 되되 공짜는 아니다.

**파괴방지**는 파괴 판정이 났을 때 그 확률로 **판정 자체를 무효로 돌린다**(단계 유지).
방지권과 달리 소모품이 아니고, 방지권보다 먼저 굴린다.

## 1-3. 밸런스 시뮬레이터와의 관계

**보너스는 시뮬레이터를 건드리지 않는다.** 새 세이브는 도감이 비어 있고 스킬 0,
고유검 0, 전설검 없음이라 네 출처가 전부 0이다. [BalanceSimulation] 이 검증하는
「맨손 신규 플레이어」가 정확히 그 상태다.

시뮬레이터에 보너스를 넣지 않는다. 넣으면 그 모형이 검증하려던 것 — 아무것도 없는
플레이어가 어디까지 가는가 — 이 흐려진다.

## 1-4. 도감 수집

지금은 검을 얻으면 **저절로** 도감에 오른다. 그래서 도감이 「지나간 자취」일 뿐
플레이어가 뭘 한 게 아니다.

바꾼다. **검을 도감에 바쳐야 칸이 열린다.** 바친 검은 사라진다.

- 강화 화면과 보관함에 「도감에 바치기」
- 이미 채운 칸이면 버튼이 뜨지 않는다 (헛되이 태우지 않게)
- 바치면 그 칸이 열리고 [ForgeBonus] 가 그만큼 오른다

「계속 강화할까, 여기서 도감에 바칠까」가 매번 선택이 된다. 지금까지 도감은
아무 결정도 요구하지 않았다.

기존 세이브의 도감 기록은 그대로 둔다 — 이미 채운 칸을 다시 요구하면 벌이 된다.

## 1-5. 대장간 스킬

`core/.../Smithy.kt`

- 최대 **15레벨**, 레벨당 성공률 +0.2%p · 파괴방지 +0.2%
- **골드로** 올린다. 값은 `Economy.upgradeCost(bestLevel) × 5 × 1.5^level`

고정값으로 두면 초반엔 못 사고 후반엔 공짜가 된다. 지금 강화 비용에 연동하면
어느 단계에서나 같은 무게다 — 강화석([GoldShop])이 쓰는 방식과 같다.

Lv1 이 사냥 두 바퀴, Lv15 가 550 바퀴쯤이다. 골드가 오래 묶일 곳이 생긴다.

`ProgressState.smithyLevel` 에 저장한다. **모드 초기화의 영향을 받지 않는다** —
도감·업적과 같은 성격이다.

## 1-6. 고유검 보유

고유검 10종은 지금 조합으로 만들면 패시브가 붙고 끝이다. 앞으로는 **한 번 발견한
사실 자체가** 보너스가 된다(`progress.uniqueFound`). 들고 있지 않아도 된다.

발견은 이미 영구 기록이라 새 저장 필드가 필요 없다.

## 1-7. 계열별 강화 특성

합산이 아니라 **든 검에만** 붙는다. 여기서 계열이 처음으로 성격을 갖는다.

| 계열 | 강화 특성 |
|---|---|
| 직검 | 성공률 +0.5%p |
| 곡도 | 담금질이 1.5배로 쌓인다 |
| 대검 | 파괴방지 +3% |
| 세검 | 담금질이 2배로 쌓인다 |
| 쌍검 | 성공률 +0.3%p, 파괴방지 +1.5% |
| 마검 | 파괴돼도 조각을 2배로 줍는다 |
| 성검 | 축복서 효과 +50% |
| 용검 | 파괴방지 +2%, 성공률 +0.2%p |
| 낫검 | 도감에 바칠 때 칸을 2개 연다(다음 단계 칸도) |
| 도끼검 | 강화 비용 -20% |
| 창검 | 강화석 요구 -2개 |
| 정령검 | 담금질 상한 +10%p |
| 합검 | 위 특성 중 절반 세기로 전부 |
| 허검 | 실패해도 강화석을 돌려받는다 |
| **전설검** | 성공률 +3%p, 파괴방지 +3%, **담금질 상한 50% → 70%** |

`FamilyStyle` 이 전투 특성을 담듯 `FamilyForge` 가 강화 특성을 담는다.
전투와 강화를 한 enum 에 섞지 않는다 — 서로 다른 이유로 바뀌는 값이다.

**전설검은 [WeaponFamily] 에 넣지 않는다.** 넣으면 계열이 15종이 되어 도감 계열칸이
294 에서 315 로 늘어나는데, 전설검은 +21 부터라 **계열칸이 있으면 안 된다** —
+0 짜리 전설검은 존재할 수 없으므로 영원히 못 채우는 칸 21 개가 생긴다.

대신 `level > RateTable.MAX_FINITE_LEVEL` 이면 전설검으로 읽는다. 판단하는 곳을
하나로 둔다.

```kotlin
/** 이 검이 전설검인지. 계열이 아니라 단계가 정한다. */
fun Sword.isLegend(): Boolean = level > RateTable.MAX_FINITE_LEVEL
```

`FamilyForge.of(sword)` 가 이것을 먼저 보고, 전설이면 계열을 무시한 채 전설 특성을
돌려준다. 도감·아트가 이미 「+21 위는 계열 무관」으로 되어 있어 결이 같다.

낫검의 「칸을 2개 연다」는 **다음 단계 칸이 비어 있을 때만** 함께 연다. 이미 차 있으면
한 칸만 연다 — 없는 칸을 억지로 만들지 않는다.

# 축 2 — 전설검 등급

## 2-1. 계열은 +20 에서 끝난다

`RateTable.MAX_FINITE_LEVEL` 이 이미 20 이라 확률표는 그대로다. 바뀌는 것은 하나 —
**+20 에서 강화 버튼이 잠긴다.**

```
  ┌──────────────────────┐
  │   여기가 계열의 끝    │
  └──────────────────────┘
  전설검은 조합소에서 벼린다
```

아트와 도감도 이미 이 구조다. 시트3 는 계열 +0~+20, 전설은 공용이고, 도감은
계열칸 294 + 전설칸 30 이다. **바꿀 것이 없다.**

## 2-2. 허검을 조합으로 내린다

허검(VOID)은 지금 **무한 회랑 10층 돌파**로만 얻는다. 전설검 재료로 쓰려면 이 문턱이
너무 높다 — 강화 게임인데 회랑 진도에 강제로 묶인다.

**도끼검 + 창검 → 허검** 으로 내린다. 둘 다 2층이라 3층(용검·정령검)과 층이 맞고,
조합 나무의 빈 가지를 채운다.

회랑 10층 보상은 남긴다 — 거기서도 얻을 수 있되 유일한 길이 아니게 된다.

## 2-3. 전설검 조합

**용검 +20 · 정령검 +20 · 합검 +20 · 허검 +20 → 전설검 +21**

넷 다 태운다. 조합소에 전용 칸으로 두고 **재료가 모자라도 무엇이 필요한지 늘 보여 준다.**
목표가 보여야 모으고 싶어진다.

```
전설검 벼리기
  ✓ 용검   +20
  ✓ 정령검 +20
  ✗ 합검   (가진 것: +14)
  ✗ 허검   (없음)
```

## 2-4. 전설검은 부서지지 않는다

파괴 판정이 나면 **+21 로 되돌아간다.** 검은 사라지지 않는다.

+44 에서 부서져 사라지면 재료 넷을 처음부터 다시 모아야 한다. 그건 몇 시간을 지우는
일이라 누를 엄두가 안 난다. 단계를 잃는 것만으로 충분히 아프다.

하락도 없다 — 전설검은 +21 아래로 내려가지 않는다.

## 2-5. 전설 해금 — 벽은 한 번만 넘는다

**전설검을 도감에 바치면 검은 사라지지만 「전설 해금」이 영구히 남는다.**

- 처음 한 번: 재료 넷 조합
- 해금 뒤: 조합소에서 **조각 500** 으로 전설검 +21 을 다시 벼린다

`ProgressState.legendUnlocked` 에 저장한다. 도감·업적과 같은 자리라 모드 초기화의
영향을 받지 않는다.

이것이 이 설계에서 가장 중요한 한 줄이다. **+21 의 벽은 게임에서 가장 높은 벽인데,
그 벽을 넘은 사람에게 다시 넘으라고 하면 아무도 두 번째 도전을 하지 않는다.**

## 2-6. 이미 +21 위인 검

불러올 때 **전부 전설검으로 바뀐다.** `Sword.family` 가 무엇이든 `level > 20` 이면
전설검으로 읽는다. 도감·아트는 이미 +21 위를 계열과 무관하게 다루므로 화면은 그대로다.

`legendUnlocked` 도 함께 켠다 — 이미 +21 위에 있다는 것은 벽을 넘었다는 뜻이다.

## 저장 호환

| 필드 | 있는 곳 | 기본값 |
|---|---|---|
| `smithyLevel` | ProgressState | `0` |
| `legendUnlocked` | ProgressState | `false` |

둘 다 기본값이 있어 옛 세이브가 손실 없이 열린다. `ignoreUnknownKeys = true` 와 함께
[SaveStore] 에 이관 코드가 필요 없다 — 모양이 바뀌는 필드가 없다.

## 테스트

- `ForgeBonusTest` — 출처별 상한, 합계 상한, 비어 있으면 0
- `SmithyTest` — 레벨 상한, 값 곡선, 골드 부족 시 못 올림
- `FamilyForgeTest` — 15계열이 각각 특성을 갖는다, 전설검이 가장 강하다
- `CodexOfferTest` — 바치면 칸이 열리고 검이 사라진다, 이미 찬 칸은 못 바친다
- `LegendCraftTest` — 재료 넷 검사, 해금 뒤 조각 경로, 해금은 초기화에 안 지워진다
- `LegendForgeTest` — 파괴 판정이 +21 복귀가 된다, +21 아래로 안 내려간다
- **`BalanceSimulationTest` 는 그대로 통과해야 한다** — 새 세이브는 보너스가 전부 0이다.
  깨지면 보너스가 시뮬레이터에 새어 들어갔다는 뜻이다.
- `BossTempoTest` 도 그대로 — 전설검은 전투 배수를 건드리지 않는다.

## 순서

1. `ForgeBonus` 뼈대 + `RateTable` 연결 (출처는 아직 없음, 전부 0)
2. 도감 수집 버튼 + 도감 보너스
3. 대장간 스킬
4. 고유검 보유 보너스
5. 계열별 강화 특성 (`FamilyForge`)
6. 허검 조합 완화
7. 전설검 등급 — +20 상한, 조합, 파괴 시 +21 복귀, 전설 해금
8. 화면 — 확률 쪼개 보이기, 대장간 화면, 조합소 전설 칸
9. 실기기 확인
