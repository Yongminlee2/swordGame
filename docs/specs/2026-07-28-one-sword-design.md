# v2.0 「검은 하나」 — 설계

2026-07-28

## 문제

이름은 검**강화** 게임인데, 실제로 플레이어가 시간을 쓰는 곳이 강화가 아니었다.

- 계열이 14종이라 "어느 검을 키울까" 가 절반을 차지했다
- 조합이 별개의 축으로 붙어 있어 강화로 돌아오는 길이 없었다
- 정작 **계열은 강화에 아무 영향이 없다.** `ForgeEngine.attempt` 는 난이도와 단계만 본다

계열 차별화가 없던 것은 아니다. `FamilyStyle` 에 계열마다 전투 특성이 있고 +15부터
계열 스킬도 열린다. 그런데 **검은 한 자루뿐이고 계열을 바꾸면 +0부터**라 한 번 고르면
끝까지 그것 하나다. 비교할 기회가 없으니 차이를 느낄 수 없었다.

축을 그림으로 그리면 이렇다.

```
강화 (손떨림) ← 사냥이 재료를 댄다        연결됨
조합 (수집)   → 계열 → 사냥에서만 의미     강화와 끊김
```

## 목표

**축을 하나로 모은다. 남는 것은 강화다.**

```
사냥  →  골드 · 강화석 · 희귀 아이템
                  ↓
강화  →  본검을 올린다  /  재료검을 정확히 +10까지 올린다
                  ↓
고단계 강화  →  그 재료검을 태운다
```

재료검을 만드는 것도 강화다. 조합이 하던 "하위를 만들어 상위로" 를 강화가 그대로
흡수하므로, 별도 시스템이 필요 없다.

## 설계

### 1. 검은 용검 하나

계열을 없앤다. 게임은 용검만 만든다.

**사라지는 것**: 조합(융합), 조합표 8식, 합검·허검, 고유검 10종, 계열 스킬 14종,
계열 해금 조건 4개, 상점의 계열 선택, 조합소 화면

**남는 것**: 사냥 24구역, 무한 회랑, 펫 24종(계열과 무관), 자리비움, 별 강화,
보관함(재료검 보관), 상점(용검·강화석·대장간)

`WeaponFamily` 열거형은 **지우지 않는다.** 옛 세이브에 `"curved"` 같은 값이 들어 있어
지우면 파싱이 깨진다. 열거형은 남기고 **불러올 때 전부 용검으로 정규화**한다.
게임 코드는 `WeaponFamily.DRAGON` 만 쓴다.

### 2. 단계가 계열의 자리를 맡는다

전투 특성은 하나(용검 = 기준값)로 두고, 사라진 14계열의 개성을 **단계 스킬로 승계**한다.
5단계마다 하나씩 열리고, 열린 것은 계속 쌓인다.

| 단계 | 열리는 것 | 원래 계열 |
|---|---|---|
| +5 | 연타 보너스 | 곡도 |
| +10 | 한 탭에 2회 타격 | 쌍검 |
| +15 | 화상 | 마검 |
| +20 | 보스 추가 피해 | 성검 |
| +25 | 조각 추가 획득 | 낫검 |
| +30 | 최대체력 비례 피해 | 허검 |
| +35 | 한 탭에 3회 찌르기 | 창검 |
| +40 | 용의 숨결(대폭발) | 용검 |

올릴수록 검이 강해지기만 하는 게 아니라 **달라진다.** 한 단계가 사건이 되는 지점이다.

### 3. 도감은 단계 도감

계열×티어 154칸 → **단계 41칸**. "몇 강까지 봤는가" 를 모은다.
부서져서 잃어도 도감에는 남으므로 파괴가 기록으로 남는다.

### 4. 그림은 314칸에서 41칸만 고른다

지금 저단계가 밋밋한 이유는 계열마다 21칸씩 채우느라 예쁜 것을 고를 여유가 없어서다.
계열이 하나가 되면 **314칸 중 41칸만** 있으면 되므로 전부 좋은 것으로 채울 수 있다.

선별 기준은 색 수와 바운딩박스로 매긴 화려함 점수다. 다만 **낮은 단계에도 하한선**을 둬서
+0부터 볼만한 검이 나오게 하고, +10부터는 확실히 화려한 것으로 배치한다.

### 5. 강화 재료는 정확히 +10짜리

| 목표 단계 | 드는 것 |
|---|---|
| ~+15 | 골드 |
| +16 ~ +25 | 골드 + 강화석 |
| +26 이상 | 골드 + 강화석 + **정확히 +10짜리 1자루** |
| +36 이상 | 골드 + 강화석 + **정확히 +10짜리 2자루** |

"+10 이상 아무거나" 가 아니라 **정확히 +10**이다. +11이 되면 재료로 못 쓴다.
재료검을 올릴 때 "여기서 멈춰야 한다" 는 긴장이 생긴다 — 강화로 만든 긴장이 하나 더 붙는다.

+0에서 +10은 하락은 있어도 파괴는 없는 구간이라 재료 만들기가 도박이 되지는 않는다.

기억할 숫자를 **+10 하나로** 통일한다. 구간마다 다른 단계를 요구하면 외울 것이 늘어난다.

### 6. 실패를 통째로 지우는 것만 못 산다

| 아이템 | 하는 일 | 상점 |
|---|---|---|
| 방지권 | 파괴 직후 눌러 검을 되살린다 | **판다** |
| 축복서 | 다음 1회 성공률 +10%p | **판다** |
| **행운부적** | 다음 1회 실패해도 하락·파괴 없음 | **뺀다** |

셋의 성격이 다르다. 방지권은 파괴 **뒤에** 2.5초 안에 눌러야 하므로 사도 손이 떨린다.
축복서는 확률을 조금 밀 뿐이다. 그런데 **행운부적은 실패라는 사건 자체를 없앤다** —
누르기 전에 이미 결과가 정해지므로 그 한 번은 손이 떨리지 않는다.
그것만 상점에서 뺀다.

행운부적 획득처는 보스 처치(낮은 확률), 사냥 이벤트, 무한 회랑 보상이다.
희소해지면 "여기서 쓸까" 가 실제 결정이 된다.

**드롭률은 감으로 정하지 않는다.** 오늘 아이템 값을 단계에 연동해 봤을 때
`BalanceSimulationTest` 가 거부했다 — 아이템을 못 사니 파괴가 자금을 통째로 지워
무한 모드 최고 도달이 +21에서 +16으로 주저앉았다.

시뮬레이터의 행운부적 구매를 드롭 모델로 바꾸고, 무한 모드가 +21 이상을 유지하는
**최소 드롭률**을 찾아 그 값을 쓴다. 방지권·축복서는 상점에 남으므로 시뮬레이터의
자금 순환은 그대로 성립한다.

무한 회랑 보상이 허검을 주고 있었는데 허검이 사라지므로 그 자리도 행운부적으로 채운다.

## 세이브 처리

지우지 않고 옮긴다.

| 옛 데이터 | 처리 |
|---|---|
| 검·보관함의 계열 | 전부 용검으로 |
| 고유검(`uniqueId`) | 일반 용검으로. 단계는 유지 |
| 도감 154칸 | 각 칸을 **그 티어의 최소 단계**로 옮겨 단계 도감에 기록 |
| 구역 정수 | 쓸 데가 사라지므로 **조각으로 환산해 돌려줌** |
| 골드·강화석·별·펫·구역 진행·업적 | 그대로 |

## 작업 순서

계열이 코드 곳곳에 박혀 있어 한 번에 하면 게임이 안 도는 구간이 길어진다.
다섯 단계로 나누고 **각 단계 끝에 설치 가능한 게임**이 되게 한다.

| | 내용 | 이 순서인 이유 |
|---|---|---|
| 1 | 계열 단일화 · 조합/고유검 제거 · 세이브 정규화 | 구조를 비워야 나머지가 붙을 자리가 생긴다 |
| 2 | 재료검(정확히 +10) · 행운부적 드롭화 · 시뮬레이터로 드롭률 확정 | 밸런스가 깨지면 1단계를 다시 봐야 한다. 일찍 확인한다 |
| 3 | 단계 스킬 8종 | |
| 4 | 단계 도감 41칸 | |
| 5 | 아트 41칸 재선별 | 눈에 띄지만 밸런스와 무관해서 마지막 |

## 테스트

- `ForgeTempoTest` — 구역 완주 1회 = 강화 5회 (유지)
- `BalanceSimulationTest` — 행운부적을 드롭 모델로 갱신하고 최소 드롭률 확정
- `LevelSkillsTest` — 단계별 해금과 누적 효과
- `MaterialSwordTest` — 정확히 +10만 재료가 된다(+9·+11은 안 된다)
- `SaveMigrationTest` — 옛 세이브(계열·고유검·정수 포함)가 손실 없이 열린다
- 계열을 세던 기존 테스트(도감 154칸, 조합표, 고유검) 삭제

## 하지 않는 것

- 계열을 5~6개로 줄이는 절충안(검 하나로 간다)
- 성공률·파괴 확률을 파는 것
- 사냥 수입 곡선 조정
