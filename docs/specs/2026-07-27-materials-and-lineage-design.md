# v1.4 "재료와 계보" 설계

2026-07-27. v1.3 실기기 플레이 이후 확장. 이번 판의 축은 셋이다 —
**고단계 강화의 화폐를 골드에서 재료로 옮기고**, **계열을 조합으로만 얻게 하고**,
**단계마다 검 그림이 달라지게** 한다. 거기에 전투 템포(5초)와 스킬, 사냥터 확장을 더한다.

## 배경

v1.3까지의 상태와 그로 인한 문제:

- 강화 비용이 전 구간 **골드만**이다. 골드는 사냥으로 무한히 벌 수 있어
  고단계 강화가 "돈 쌓기"의 반복이 된다. 보관함·분해·사냥이 강화와 끊어져 있다
- 계열 14종이 상점·드롭에 섞여 나온다. 분류가 많은데 각각을 얻는 감각이 없고,
  조합은 "더 높은 단계의 같은 검"을 만드는 부수적 장치에 머문다
- 검 그림이 **티어 11종**이라 +3과 +5가 같은 그림이다. 한 단계 올린 보람이 눈에 안 보인다
- 보스 제한시간 20초 · 회랑 층 25초는 늘어진다. 긴장이 한 점에 모이지 않는다

## 1. 강화 비용 — 고단계는 돈이 아니라 재료

| 구간 | 요구 |
|---|---|
| +0~+12 | 골드만 (현행 유지 — 초반 리듬을 건드리지 않는다) |
| +13~+15 | 골드 + **검 1자루** |
| +16~+20 | 골드 + **검 2자루** + **강화석 3~8** (단계마다 +1) |
| +21~ (무한) | 골드 + **검 3자루** + 강화석 `8 + (단계-20)`, 상한 40 |

- 재료가 없으면 **강화 버튼이 눌리지 않는다**. 성공률 보너스가 아니라 입장료다
- 재료로 쓰이는 검은 보관함에서 **낮은 단계부터 자동으로** 집는다. 고르는 화면을 하나 더
  두면 강화 리듬이 끊긴다 (v1.3 재료 강화와 같은 방침)
- 기존 "재료 강화(성공률 +)"는 **필수분 위에 얹는 선택**으로 남는다.
  필수 2자루 + 추가 3자루까지 → 성공률 보너스는 추가분에만 붙는다
- 이 변화가 사냥·보관함·분해를 강화의 **전제 조건**으로 만든다.
  골드만 쌓아서는 +16을 넘을 수 없다

### 파산 구제와의 관계

파산 구제(골드 0 + 검 없음)는 그대로 둔다. 재료가 없어 강화를 못 하는 것은
파산이 아니라 **사냥할 이유**이므로 구제 대상이 아니다.

## 2. 강화석

새 자원 하나. 조각(shards)과 별개다 — 조각은 조합소·스타포스가 먹고,
강화석은 고단계 강화만 먹는다. 두 자원이 같은 수요를 다투면 어느 쪽도 특별하지 않다.

| 획득 경로 | 양 |
|---|---|
| 잡몹 처치 | 5% 확률로 1개 |
| 보스 처치 | 확정 3~8개 (구역 깊이 비례) |
| 검 분해 | 조각과 함께 1~3개 (단계 비례) |
| 조합소 교환 | 조각 20 → 강화석 1 |
| 회랑 보상 | 층 비례 |

## 3. 계열 정리 — 기본 4종 + 조합 전용 10종

시작은 **직검 하나뿐**이다. 계열이 열리는 것 자체가 진행의 이정표가 된다.

| 기본 계열 | 해금 조건 |
|---|---|
| 직검 | 처음부터 |
| 곡도 | 아무 검 **+10** 달성 (`stats.bestLevelEver >= 10`) |
| 대검 | **서로 다른 구역 3곳**의 보스 클리어 (`clearedZoneIds.size >= 3`) |
| 세검 | **고유검 1개** 발견 (`uniqueFound.isNotEmpty()`) |

나머지 10계열(쌍검·마검·성검·용검·낫검·도끼검·창검·정령검·합검·허검)은
**조합으로만** 나온다. 상점·드롭에 절대 등장하지 않는다.

### 기존 세이브 처리

v1.3 세이브는 업적으로 이미 해금된 계열을 갖고 있다. 계열 해금은
`ProgressState`(전역 진행도)가 판단하므로, **이미 달성한 조건은 소급 적용**된다.
+10을 넘긴 세이브는 곡도가 처음부터 열려 있다. 잃는 것은 없다.

## 4. 조합표 — 계열의 유일한 출처

조합 결과가 "가장 많이 넣은 계열"이던 것을 **명시적 표**로 바꾼다.
표에 없는 조합은 기존 규칙(최고 단계 + 보너스, 계열은 최다 계열)을 따른다.

**조회 규칙**: 재료의 **계열 집합**(중복 제거)으로 표를 찾는다. 재료 수는 2~4 아무거나다.
직검 2자루든 3자루든 집합은 `{직검}` 이라 똑같이 쌍검이 된다 — 자루 수는 결과 **단계**에만
영향을 준다. "서로 다른 4계열"만 재료 4자루를 요구한다.

| 재료 (계열 집합) | 결과 |
|---|---|
| 직검 + 직검 | 쌍검 |
| 직검 + 대검 | 도끼검 |
| 곡도 + 곡도 | 낫검 |
| 세검 + 세검 | 창검 |
| 직검 + 곡도 | 마검 |
| 대검 + 세검 | 성검 |
| 마검 + 성검 | 용검 |
| 낫검 + 창검 | 정령검 |
| 서로 다른 4계열 | 합검 |
| (회랑 10층 보상) | 허검 |

- **조합표는 도감에 공개한다.** 계열을 모으는 길이 보여야 조합소에 갈 이유가 생긴다.
  숨기는 것은 고유검 10종 레시피뿐이다 — 그쪽은 발견이 재미다
- 결과 단계는 현행 규칙 그대로: 최고 단계 + (재료 수 - 1) + 같은 계열 보너스, 상한 +20
- 우선순위: **고유검 레시피 → 조합표 → 기존 일반 규칙**

## 5. 단계마다 다른 그림 — 314칸

- **계열 14 × +0~+20 = 294칸**을 전부 다른 그림으로
- **전설 20칸**: +21~+30은 폴더의 CC0 아티팩트(케레보프의 검·힘의 검·피의 재앙·
  디스페테르의 지팡이 등 104종에서 선별), +31~+40은 웹에서 구한 무료(CC0/CC-BY) 렌더형
- **+41 이상은 마지막 그림에 오라만** 짙어진다. 상한 없는 구간을 그림으로 좇을 수는 없다

### 원본 편차와 그 처리

CC0 타일이 계열마다 크게 다르다:

| 계열 | CC0 타일 수 |
|---|---|
| 직검 | 409 |
| 정령검 | 173 |
| 도끼검 | 151 |
| 창검 | 97 |
| 곡도 | 85 |
| 대검 | 38 |
| 세검 | 30 |
| 마검 | 20 |
| 낫검 | 9 |
| 성검 | 7 |
| 용검 | 2 |
| 쌍검 | 0 (전부 합성 dual) |

21종을 못 채우는 계열은 이렇게 채운다:
1. **형태가 맞는 타일을 다른 폴더에서 빌린다** — 용검은 곡도·대검의 물결날,
   성검은 직검의 십자 코등이 계열, 낫검은 창검의 곡선날
2. **쌍검은 X자 합성** — 단일 검 타일 두 장을 좌우로 겹쳐 그린다(원본 dual 타일과 같은 방식)
3. 그래도 남는 칸은 **티어 색 등급**(원본색 35% + 티어색 65%)으로 채운다

직검·도끼검·정령검·창검·곡도는 21단계가 전부 실제로 다른 그림이 된다.

### 저작권 경계

사용자가 모아 둔 폴더에는 **두 종류가 섞여 있다.** 영문 타일명(`sword_roman_ruby`,
`urand_wyrmbane` 등, 약 320종)은 Dungeon Crawl 계열 CC0이라 쓴다.
한글 이름 파일(용마제구검·이가닌자의검·`아스타로트 - 대지 {대인용}` 등, 약 1,700종)은
상업 게임에서 추출된 스프라이트로 보여 **쓰지 않는다.** 이 경계는 협상 대상이 아니다.

## 6. 스킬 — +15부터 계열마다 하나

강화 단계 **+15 이상**이면 탭할 때 **12% 확률**로 계열 고유 스킬이 발동한다.
화면에 스킬 이름이 크게 뜨고 데미지가 배로 들어간다.

| 계열 | 스킬 | 효과 |
|---|---|---|
| 직검 | 일섬 | 3배 |
| 곡도 | 월광참 | 2.5배 |
| 대검 | 붕괴 | 5배 |
| 세검 | 연속 찌르기 | 1배 × 4연타 (합 4배) |
| 쌍검 | 쌍월 | 2배 × 2회 |
| 마검 | 흡혈 | 3배 + 조각 1 |
| 성검 | 심판 | 보스에게 6배 (잡몹 3배) |
| 용검 | 용의 숨결 | 3배 + 화상 폭발 |
| 낫검 | 사신의 낫 | 3배 + 최대체력 5% |
| 도끼검 | 분쇄 | 6배 |
| 창검 | 관통 | 1.2배 × 3연타 (합 3.6배) |
| 정령검 | 정령 폭발 | 3배 + 화상 |
| 합검 | 만상 | 4배 |
| 허검 | 공허 | 3배 + 최대체력 8% |

- 판정은 `:core` 순수 함수. 난수를 값으로 받아 테스트가 결정적이다 (치명타와 같은 방식)
- 치명타와 **중첩된다** — 스킬 + 치명타가 겹치면 그 판이 뒤집힌다.
  5초 보스전에서 이 순간이 승패를 가른다
- 스킬은 강화 단계를 올릴 이유를 하나 더 만든다. +15는 파괴 구간 한복판이라
  "위험을 무릅쓸 값어치"가 생긴다

## 7. 템포와 사냥터 확장

### 제한시간 5초

- **사냥터 보스 20초 → 5초** (전 구역)
- **회랑 층 25초 → 5초**, 층당 잡몹 **5마리 → 2마리**
  (5초에 5마리는 물리적으로 불가능하다. 마리당 체력은 그대로 둔다)
- 체력은 건드리지 않는 것이 원칙이나, **시뮬레이션으로 검증한다** —
  구역별 권장 단계에서 실제로 잡히지 않으면 보스 체력을 내린다.
  판단 기준: `Combat.canBeatBoss(권장 단계 검, 구역)` 이 참이어야 한다

### 12구역 × 5종 = 60몬스터

- 구역마다 잡몹 **3종 → 5종**
- 신규 구역 2개: **천공 회랑**(권장 +22) · **폐허 왕도**(권장 +26).
  무한 회랑 앞에 붙어 후반 사냥터가 생긴다
- 몬스터 시트 재생성: 60잡몹 + 12보스 + 펫 10 = **82칸** (8열 11행).
  DCSS 몬스터 타일 547종이 있어 원본은 충분하다

## 8. 구조

새 `:core` 객체 — 전부 순수 함수, JVM 테스트:

- `ForgeCost` — 단계별 요구(골드·검 수·강화석) 계산. 강화 가능 판정
- `FusionTable` — 조합표 조회
- `Skills` — 계열별 스킬 정의와 발동 판정

기존 파일 변경:

- `Model.kt`: `GameState.forgeStones: Int = 0` (기본값이라 세이브 호환)
- `Progress.kt`: 계열 해금 조건 3종 (업적 대신 진행도 조건)
- `Combat.kt`: `hit()` 에 `skillRoll` 추가, `Hit.skill: Skill?` 반환
- `ForgeEngine.kt`: `canAttempt` 가 재료·강화석을 본다
- `Fusion.kt`: 조합표를 고유검 레시피 다음 순위로 조회
- `Zones.kt`: 구역 12개, 몬스터 5종씩, `bossSeconds = 5`
- `Gauntlet.kt`: `FLOOR_SECONDS = 5`, `WAVE_SIZE = 2`

새 도구:

- `tools/make_sword_sheet3.ps1` — 314칸 시트. 계열별 타일 풀을 키워드로 자동 선별,
  부족분은 색 등급. ASCII 전용 스크립트(PS 5.1 ANSI 함정)
- `tools/make_monster_sheet.ps1` 갱신 — 82칸
